# Spec：FumiGit — 日常写路径闭环（分支操作 · 工作区安全 · 同步补全）

> 来源：2026-10-07 grilling 会话共识。决策 #1–#10 均经用户逐条确认。

## Problem Statement

开发者日常用 Git 时最高频的写路径——**建分支做新功能、迁出分支、暂存半成品、丢弃改坏的工作区、同步远程**——在 FumiGit 里都还要退回终端。现状:点侧栏分支只能定位提交不能迁出;分支的新建/删除/改名完全缺失;push 在无上游分支时直接报错让用户去终端敲 `git push -u`;pull 遇到本地与远程分叉也直接报错;改坏的文件没有丢弃入口;stash 没有任何 UI。结果是「看图谱」闭环了,「干活」没闭环——图谱再好也只是阅读器。

## Solution

在本批交付后,开发者可以**不碰终端完成日常循环**:在侧栏或提交图谱上右键即可建分支/迁出/改名/删除,在新分支上开发;随时把半成品 stash 进侧栏的 stash 区;改坏了就右键丢弃;推送时若分支没有上游,弹框选远程一键 `push -u` 建立关联;拉取遇到分叉时,弹确认后应用内完成 merge,真出冲突则列出冲突文件并提供「中止合并」安全出口。所有会销毁改动的操作(丢弃、reset --hard、脏树迁出)都先被拦截,用户在明确的对话框里做知情选择,不会无感丢工作。

## User Stories

**分支操作**

1. 作为开发者,我想在侧栏右键任意本地分支并选择「迁出」,以便切换到该分支继续工作。
2. 作为开发者,迁出后我想看到当前分支标识移动、图谱与状态面板联动刷新,以便确认切换成功。
3. 作为开发者,我想通过侧栏顶部按钮新建分支,默认建完即迁出、可勾选「仅创建」,以便开新功能时少一步操作。
4. 作为开发者,新建分支时我想得到名称校验反馈(重名、非法字符、非法前缀),以便在提交表单时就纠正而不是等 git 报错。
5. 作为开发者,我想右键分支进行重命名,以便修正随手起的错名。
6. 作为开发者,删除已合入的分支时我想只需一次确认,以便快速清理用完的分支。
7. 作为开发者,删除未合入分支时我想先看到未合入提交数,再做一次明确标注「强制删除」的二次确认,以便不会无意识丢掉只有它保留的提交。
8. 作为开发者,当前分支在右键菜单里应显示为不可删除,以便我不会尝试一个 git 本身就不允许的操作。
9. 作为开发者,在提交图谱上右键一个挂着本地分支的提交,我想直接看到「迁出到 <分支名>」,以便按提交位置思考时不必回侧栏找分支。
10. 作为开发者,在提交图谱上右键任意提交,我想「在此新建分支」,以便把历史中的某个点快速变成工作起点。
11. 作为开发者,在提交图谱上右键任意提交,我想将当前分支重置到此提交并可选软/混合/硬三种模式,以便撤销本分支上尚未推送的错误提交。
12. 作为开发者,对任意提交我不会看到「直接迁出此提交」(detached HEAD)入口,以便不进入后续写操作语义复杂的悬空状态。

**安全模型(拦截与知情选择)**

13. 作为开发者,工作区有未提交改动时我尝试迁出其他分支,我想看到拦截对话框列出受影响文件,并可选「带着改动迁出 / stash 后迁出 / 取消」,以便我在知情的情况下决定改动去向。
14. 作为开发者,「stash 后迁出」应把改动存入 stash 区后再切换、不自动恢复,以便改动安全地留在 stash 列表里随时找回。
15. 作为开发者,我尝试 reset --hard 或丢弃改动而工作区脏时,我想被同样拦截并确认,以便不会一键销毁未提交工作。
16. 作为开发者,丢弃已暂存的改动时我想被提示这些改动会连同暂存状态一起消失,以便确认的动作与实际发生的动作一致。

**同步补全**

17. 作为开发者,推送一个没有上游的分支时,我想弹出远程选择框(默认 origin,仅一个远程时锁定)并一键「建立关联并推送」,以便不必去终端敲 `push -u`。
18. 作为开发者,推送/拉取/迁出等操作后,工具栏的 ahead/behind 徽章与图谱 ref 应立即刷新,以便 UI 始终反映真实仓库状态。
19. 作为开发者,拉取遇到本地与远程分叉时,我想看到「合并 origin/<分支> 到当前分支」的确认框而非报错,以便在应用内完成这一日常高频动作。
20. 作为开发者,merge 真的产生冲突时,我想看到冲突文件清单(带冲突状态标识)与「中止合并」按钮,以便合并卡住时有明确出口,解决动作我可以在终端完成或等第二批冲突 UI。
21. 作为开发者,「中止合并」应把仓库完整恢复到合并前状态(等价 merge --abort,仅在合并进行中可用),以便任何时候都能安全反悔。

**丢弃改动**

22. 作为开发者,我想在变更列表右键单个文件「丢弃改动」,以便只撤销某一个改坏的文件。
23. 作为开发者,我想对未跟踪文件右键「删除文件」,以便清理实验产物。
24. 作为开发者,我想通过变更面板底部按钮「全部丢弃」,以便一键回到干净工作区。
25. 作为开发者,每次丢弃前我都想看到确认弹窗并明确告知不可恢复,以便这类操作永远出于我的本意。

**stash**

26. 作为开发者,我想一键 stash 全部改动并可附可选描述,以便在任务被中断时快速存下半成品。
27. 作为开发者,我想在侧栏看到 stash 列表(含描述与时间),以便找回记忆中的存档。
28. 作为开发者,我想展开任意 stash 条目只读查看其 diff,以便确认里面存的是什么再恢复。
29. 作为开发者,我想对 stash 条目执行「恢复(保留副本)/ 恢复(弹出)/ 删除」,以便灵活管理存档。
30. 作为开发者,pop/apply stash 遇到冲突时,我想得到明确报错且 stash 条目不被销毁(pop 失败时保留),以便存档不会在失败中丢失。

**通用**

31. 作为开发者,所有写操作执行中我想看到进行中反馈并防止重复触发,以便不会并发发起两个 git 写操作。
32. 作为开发者,任何操作失败时我想看到可读的中文错误信息(基于结构化 GitError 规整),以便知道下一步该做什么。

## Implementation Decisions

以下决策来自 grilling 会话逐条确认:

- **范围与顺序**:第一批 = 分支操作(迁出/新建/删除/改名)+ 提交右键菜单(建分支/reset)+ 脏工作树安全弹窗 + push -u + 丢弃改动 + stash(全量)+ 分叉拉取最小 merge。合并冲突解决 UI、worktree、revert/cherry-pick、rebase、tag、remote 管理、force push 全部后置。
- **入口**:分支操作走侧栏分支右键菜单 + 侧栏顶部「新建分支」;提交图谱右键菜单为新增通用菜单组件,侧栏与图谱共用;单击分支保持现有「仅定位」行为不变。
- **提交右键菜单动态项**:菜单项按提交上挂的 ref 动态出现——挂本地分支才显示「迁出到 <分支名>」;「在此新建分支」「重置当前分支到此(软/混/硬)」对所有提交可用;不提供 detached HEAD 迁出。
- **安全模型**:前端在发起迁出 / reset --hard / 丢弃前检查工作区状态,脏则拦截并弹选择对话框(带改动继续 / stash 后继续 / 取消);「stash 后迁出」为 stash push → 迁出、不自动 pop。拦截判断在前端,git 自身的拦截(如 checkout 冲突)作为最后防线,错误需规整为可读信息。
- **分支删除语义**:删除前检测是否已合入当前分支(基于 rev-list 计数);已合入一次确认即删;未合入展示未合入提交数并要求二次确认后才执行强制删除;当前分支不可删(菜单禁用)。
- **push 补全**:无上游时弹远程选择框,远程列表来自 git remote;单远程时锁定默认项;确认后执行带 `-u` 的建立关联推送;force push 本批不做。
- **分叉拉取最小 merge**:pull 分叉时改为弹确认框显示合并目标(上游分支名),确认后执行普通 merge;成功则按常规流程刷新;冲突时从状态中提取未合入(unmerged)文件清单展示,并提供「中止合并」;解决动作本批留给终端。
- **合并状态契约**:仓库状态需扩展出「合并进行中」与未合入文件清单(按 porcelain 冲突状态码解析),前端据此渲染冲突清单与「中止合并」按钮;「中止合并」仅在合并进行中可用。
- **stash 契约**:stash 条目含描述、时间、可展开的只读 diff(复用现有 diff 渲染);操作为全量 stash(不含部分暂存);pop 失败(冲突)时 stash 条目必须保留——这意味着 pop 场景需保留条目直至确认成功。
- **IPC 与架构约定**:所有新增 git 能力走既有三层同步(命令定义 → invoke 注册 → 类型化包装),组件不直接 invoke;结构化错误沿用 tagged GitError,可按需增加错误 kind(如冲突/脏树类),前端经既有规整函数统一呈现。
- **UI 基元**:右键菜单与确认/选择对话框为本批新增的两个基础 UI 组件,样式遵循既有设计令牌;若需新增令牌或布局位,先在 ui-spec 增补条目再写码(规则先行)。
- **新建分支默认值**:表单默认「创建并迁出」,可勾选「仅创建」;reset --hard 必过安全弹窗;丢弃已暂存改动时提示将连带退回暂存状态。

## Testing Decisions

- **好测试只测外部行为**:Rust 侧在真实 git 构造的夹具仓库上执行操作,断言后续 git 状态(log/status/branch 输出),不 mock git 本身;前端侧断言状态流转与用户可见结果,不断言内部调用细节。
- **只用两道既有接缝,不新建接缝**:
  1. **Rust git 封装层公开函数**(cargo test,真实 git + tempfile 夹具仓库):覆盖迁出(含脏树被 git 拦截的报错形态)、建/删/改分支、已合入检测、stash 全套(含 pop 冲突时条目保留)、merge 与中止(含未合入文件清单解析)、丢弃、push -u。先例:git.rs 现有测试。
  2. **前端 store 状态流转**(vitest,mock IPC):覆盖写操作成功后的刷新联动、错误规整呈现、拦截弹窗的触发条件(脏工作树 × 操作类型)。先例:repo.test.ts。
- UI 组件(右键菜单、对话框、stash 区)不做单元测试,遵循仓库既定约束(前端测试只覆盖纯逻辑)。

## Out of Scope

- 合并冲突解决 UI(三方视图、标记已解决、逐块取舍)——第二批重头戏,本批冲突场景以「清单 + 中止合并」收口。
- revert / cherry-pick / rebase(遇冲突需要冲突 UI)。
- worktree 管理、tag 管理、remote 管理、force push。
- detached HEAD 迁出与「从 detached 建分支」出口。
- 部分暂存类 stash(--keep-index / 指定路径)、pull --rebase 策略切换。
- 凭据管理(继续继承用户 git credential helper / SSH agent)。
