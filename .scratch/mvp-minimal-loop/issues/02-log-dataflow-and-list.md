# 02 — 提交数据流 + 虚拟滚动列表

**What to build:** 打开仓库后，中央区域显示该仓库的提交列表：每行含提交信息、作者（头像色点 + 名字）、相对时间、短 hash。列表用虚拟滚动，滚到十万行也不卡顿、数据分页加载。此工单打通"Rust 解析 → IPC → 前端 store → 列表"的完整数据流。

Rust 侧完成 `get_log`：spawn git，解析 log 的 porcelain/format 输出为结构化提交（含 hash、作者、时间、信息、父提交、ref 列表）。lane 分配算法作为纯函数以 TDD 落地（本工单先保证算法与单测正确，Canvas 绘制是下一张票）：按时间倒序遍历，first parent 延续当前 lane，其余 parent 各开新 lane（从 8 色调色板取色），空 lane 立即回收压缩。

测试夹具矩阵在此票补齐：空仓库、单分支线性、多分支合并拓扑、分离 HEAD、中文路径、非 UTF-8 提交信息。

**Blocked by:** 01（打开仓库与封装层骨架）。

**Status:** ready-for-agent

- [ ] 打开真实仓库后列表正确渲染提交信息/作者/时间/hash
- [ ] porcelain 解析测试覆盖夹具矩阵（真实 git 临时仓库，不 mock）
- [ ] lane 分配纯函数测试通过：线性单 lane、分叉开新 lane、合并回收 lane、颜色循环
- [ ] 分页：滚到底部增量加载，直到历史尽头显示终止提示
- [ ] 空仓库显示引导空态，不报错
- [ ] 中文路径与中文提交信息不乱码
