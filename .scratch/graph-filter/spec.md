# Spec：提交图谱筛选（分支 · 提交者 · 日期）

> 来源：2026-10-13 与用户的会话。用户给出同类客户端三块筛选下拉的截图（分支 / 提交者 / 日期），
> 要求「参考实现这三块筛选功能」。三块筛选的形态与选项由截图直接给定；其余细节由 agent 按推荐方案代持，
> 在 Implementation Decisions 中标注，可随时推翻。

## Problem Statement

FumiGit 的图谱恒为「所有分支 × 全量时间 × 全量提交者」：`get_log` 固定 `--all`，
唯一能收窄列表的手段是工具栏搜索框，而它是**客户端子串过滤**（只在已加载的那几页里过滤）。
两个真实后果：

1. 多分支仓库里图谱被所有分支的历史摊平——ui-spec §1 图谱列已实测本项目 20 分支 / 21 lane，
   并写明「真正能降下来只有减少并发 lane（`get_log` 去掉 `--all`）」。想看某一条分支的历史，
   用户只能自己在脑子里过滤。
2. 按人 / 按时间找提交只能滚动翻页，翻到哪算哪，且**翻页与过滤不同步**：客户端过滤下
   「没有匹配项」并不等于「历史里没有」，空态会骗人。

## Solution

新增图谱筛选栏（分支 / 提交者 / 日期三块下拉），三个维度一律**下推到 git**：
`get_log` 扩展可选参数 `LogFilter { branch, author, since }`。

- 分页语义保持正确：`--skip` / `--max-count` / `done` 都在**过滤后**的结果集上计算，
  不会出现「翻了两页才发现匹配项都在更深处」，空态即真相。
- 分支筛选顶掉 `--all`，把并发 lane 收窄到该分支可达集合（顺带解决了 §1 记录的性能/可读性对冲）。
- 提交者用 `--author` + `--fixed-strings`：git 的 `--author` 默认按**正则**解释，
  用户输入 `a.b` 会误伤 `axb`，必须固定串匹配。
- 日期用 `--since`：最近 24 小时 / 一周 / 一月（`24 hours ago` / `7 days ago` / `1 month ago`）。
- 「只看我的」需要身份：新增 `get_user_identity`（`git config user.name / user.email`），
  两者都未配置时该入口禁用并给 hint。

## User Stories

1. 作为开发者，我想按分支筛选图谱（默认「所有分支」），以便只看某条分支上的提交。
2. 作为开发者，我想按提交者筛选：全部 / 只看我的 / 从「最近提交者」列表（带提交数）里挑一个 /
   直接输入姓名或邮箱回车过滤，以便找到某个人做过什么。
3. 作为开发者，我想按时间筛选（全部时间 / 最近 24 小时 / 最近一周 / 最近一月），以便只看近期的提交。
4. 作为开发者，当筛选结果为空时我想看到「当前筛选下没有提交」而不是「这个仓库还没有提交」，
   并能就地把筛选清掉，以便区分「筛选筛没了」和「仓库真的空」。
5. 作为开发者，当有筛选在生效时我想有一个「清除筛选」入口一键回到默认视图，以免记不清自己开了什么。
6. 作为开发者，我想让筛选在翻页 / 刷新 / 外部改动触发的 refresh 之间保持生效，以便不被静默重置。

## Implementation Decisions

- **筛选下推 git**（不是客户端过滤）：语义正确、分页正确、分支筛选真能收窄 lane。
- **「最近提交者」计数按已加载提交统计**（`authorStatsOf(commits)`，一趟 O(n)，不做全量历史扫描）；
  按提交者筛选生效时**保持上一份快照**——否则列表会被自己的筛选收窄成只剩一个人，无法再切到别人。
- **三块下拉复用右键菜单基元** `ContextMenu`，为其补五个能力：`checked`（勾选项）、
  `kind: "header"`（分组标题）、`footer`（下拉内输入框）、`maxListH`（长列表内滚）、
  `anchor`（锚点内按下不关闭，按钮才能正常 toggle）。右键菜单渲染不变：只有列表里出现过 `checked` 才占勾选位。
  同时修掉基元的一个潜在缺陷：容器内滚动会关掉菜单（长列表内滚必须不关）。
- **「只看我的」的过滤值** = `user.email` 优先，退化到 `user.name`；两者皆无 → 入口禁用 + hint「未配置 user.email」。
- **分支筛选只列本地分支**（`refs` 中 kind=branch），值在后端按 `refs/heads/<name>` 校验存在后再传给 git
  （避开与同名标签的歧义），并拒绝以 `-` 开头的值防参数注入。
- **工具栏搜索框保持不变**（客户端子串过滤，mvp 故事 11）。搜索过滤「已加载的」，筛选改变「加载什么」，
  两者正交、可叠加，不合并。
- **筛选栏渲染在历史 tab 内**（改动 tab 下筛选没有作用对象，不展示，避免凭空多一行）；
  筛选状态**不持久化**，关仓库/换仓库即回默认。
- **时间范围串由后端白名单映射**（前端只传 `day|week|month`），不接受任意日期表达式。

## Out of Scope

- 搜索框下推 git（`--grep`）——保持既有语义，另开工单。
- 筛选状态写入 app config 持久化。
- 远程分支 / 标签作为筛选维度（截图里也只有本地分支）。
- 多选筛选（截图三块都是单选）。

## Test Decisions

- Rust（真实 git 夹具）：`get_log` 的分支 / 作者 / 固定串 / 时间四类过滤 + 非法参数拒绝
  （不存在的分支、非法时间范围、以 `-` 开头的分支名）；`get_user_identity` 读本地 config 且空值规整为 `None`。
- 前端（打桩 IPC）：`authorStatsOf` / `logFilterActive` / `authorPattern` 纯函数断言；
  store 流转断言——切筛选重取第一页且保留已加载深度、选中项被筛掉即收起、`loadMore`/`refresh` 带当前筛选、
  提交者筛选生效时作者统计不被收窄。
- 验收命令：`cargo test`（在 `src-tauri/`）+ `pnpm test` + `pnpm build`（含 tsc 类型检查）。

## 评审整改（2026-10-13 单轮只读评审后定稿）

评审报了 8 条，逐条落地如下（其余结论为「未发现问题」）：

1. **并发串味（真实缺陷，已修）**：`loadMore` 在 await 前取 `commits` 快照并无条件写回，会把旧视角/旧仓库的页灌进新列表；`reloadLog` 也没有代次校验（后到的慢响应盖掉新筛选）。
   引入单调 `logToken`：`reloadLog` / `refresh` 递增代次并在落地前校验，`loadMore` 只记录代次 + 仓库身份 + 列表长度，三者任一变化即丢弃这一页。`openRepo` / `closeRepo` 补 `loadingMore: false`（否则换仓库时在飞的分页会把 `loadingMore` 卡在 true）。
2. **日志失败拖死整个刷新（真实缺陷，已修）**：`refresh` 的 `Promise.all` 里只有 `getLog` 没有兜底，筛中的分支被删除后每次刷新都在这里炸掉，`status/summary/refs` 全都不落地——而「先把 refs 刷出来才知道分支没了」正是循环依赖。
   抽出 `fetchLogFirstPage()`：日志失败不再中断其余数据面；失败且筛在某个分支上时**退回「所有分支」重试一次并提示**（自愈，不让图谱永远卡在一项已消失的筛选上）。
3. **身份瞬时失败把入口变灰（已修）**：`refresh` 用 `identity ?? get().identity` 保留上一份。
4. **参数注入断言恒真（已修）**：`--all` 分支名的错误文案与「分支不存在」可区分，断言改为校验「非法分支名」，删掉 `starts_with('-')` 检查就会红。
5. **「最近提交者」行没有勾选反馈（已修）**：生效中的提交者行打勾；但生效值等于「只看我的」时不再重复勾同名统计行（避免两处同时打勾）。
6. **`--since` 语义（决定保留并记录）**：git 的 `--since` 按 **committer date** 过滤、且走到更老的提交会提前停止遍历（`--since-as-filter` 才是全集合过滤，但要求 git ≥ 2.37）。本项目**保留 `--since`**：与主流客户端一致、且在超大仓库上省一趟全历史遍历；代价是 rebase/amend 过的提交（作者时间老、提交时间新）会出现在「最近 24 小时」里。文案仍写「最近」而非精确语义，此为该决策的已知取舍。
7. **基元关闭条件无自动化覆盖（接受，记录）**：本仓库没有 jsdom / @testing-library，`ContextMenu` 的 mousedown / scroll 关闭条件只能人工验证；SSR 冒烟覆盖结构与勾选位占位逻辑。要补交互测试需先引入 DOM 测试栈，属另开工单的依赖决策。
